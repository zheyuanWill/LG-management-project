## 第二轮排查（用户实测反馈：下载报错 + 404 + 三个概念问题）
用户贴了 4 类问题，逐条定位：
- **下载/预览 `SignatureDoesNotMatch`**：根因 = 预签名 URL 用内部 `minio:9000` 主机签名，但浏览器访问 `localhost:9000`，SigV4 的 host 校验不一致。旧代码 `file_service.get_minio_url` 在签名后再替换 netloc，反而破坏签名。✅ 修复：新增 `dependencies.get_minio_public_client()`（用 `MINIO_PUBLIC_ENDPOINT` 签名，仅本地签名不联网），`get_minio_url` 改用它并删掉 netloc 替换 hack。后端卷挂载热更新已生效（无需重建）。
- **`POST /tasks/tasks/16/daily-updates` 404**：根因 = 前端 `DailyUpdateForm.tsx` 拼了重复 `/tasks/` 段（apiClient baseURL 已是 `/api/v1`，router 前缀已是 `/tasks`）。✅ 修正为 `/tasks/${task.id}/daily-updates`。同时修正 `TaskList.tsx` 创建任务 URL（旧 `/projects/${id}/tasks` → `/tasks/projects/${id}/tasks`）。后端不需要重建（卷挂载）。
- **“应看到每个任务的历史版本”**：后端本就有 `GET /tasks/{id}/daily-updates`（按日期倒序），但前端无展示。✅ 新增 `frontend/src/components/task/DailyUpdateHistory.tsx`（懒加载、`enabled:open`），并在 `TaskItem.tsx` 加「历史记录」按钮。需重建 frontend 镜像（已 `docker compose build frontend` 成功并 `up -d frontend`，容器 dist 含 `历史更新记录` 字样）。
- **随手存图片返回空 suggestions**：**非 bug，是设计**。`backend/ai_service/main.py` 只有 chat/embed/qa，**根本没有 `/v1/ocr` 端点**；`quick_save_service.recognize_content("image")` 注释写明“OCR 已移除（依赖较重）”。图片已正常保存到 MinIO（`file_key` 有值），只是不提取文字 → 无项目联想建议。要在图片→文字需新建 OCR 端点（paddleocr/tesseract，体积大、CN 网络构建易失败），属独立大功能，已向用户说明并询问是否要做。
- **RAG 知识库会话存储**：**仅 localStorage（临时、按浏览器、不跨设备同步）**，唯一用到的是 `frontend/src/components/knowledge/QAChat.tsx`。后端 `knowledge` 只存文档+向量，不存对话历史。要跨设备需新增 `ChatSession/ChatMessage` 模型 + `/knowledge/sessions` 接口。已说明并询问。
- **所有模块文件是否进文件中心**：**否**。只有 `POST /files/upload` 写 `FileModel`；知识库/任务照片/备件/随手存都直接存 `file_key` 绕过 files 表（`/files/url` 按 key 取 URL，但列表里看不到）。统一需在各上传处补写 FileModel 行。已说明并询问。

- **已知接缝（非本轮范围，待修）**：`DailyUpdateForm` 提交时把 `photos[]` 随表单上送，但后端 `create_daily_update` 不消费 photos、也未调 `/daily-updates/{id}/photos` → 每日照片实际不会持久化（仅前端本地预览）。
