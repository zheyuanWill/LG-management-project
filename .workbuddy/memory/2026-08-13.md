### #1 MOA合同上传 422 (Word 被拒)
- **根因**：`apiClient`（frontend/src/lib/api.ts）默认 `'Content-Type': 'application/json'`。FormData 发送时 axios 应自动覆盖为 `multipart/form-data`，但显式 default header 阻止覆盖 → 后端收到 JSON 格式请求，无法解析 file 字段 → 422 "payload file is empty"。
- **修复**：移除 apiClient 的默认 Content-Type（让 axios 根据 data 类型自动选择）。
- **影响范围**：所有通过 `useApiPost` + FormData 的上传（MOA 合同、SparePhotos、HKSignature 等）。

### #C RAG 知识库端到端 + 大文件能力确认
- **架构**：FastAPI + pgvector（PostgreSQL `vector(512)` 扩展）+ fastembed（BAAI/bge-small，512维，CPU推理）。**不需要 ChromaDB**——pgvector 已做向量存储 + 余弦距离检索。
- **端到端验证成功**：`/knowledge/query` 用**所有已上传且有 embedding 的文档**作为检索语料（按 category 可选过滤），返回答案 + 引用来源（doc标题/chunk/score）。实测问答返回准确答案 + 5 条 citations。
- **当前限制**：
  1. PDF 文本提取用 **PyPDF2**——对**扫描版 PDF（图片型）提取为空** → 入库失败（无文字则 chunk 为空 → embedding 跳过）。用户说的"300页有图有文字表格"如果是扫描版会失败。
  2. **Word 表格**提取成 ` | ` 分隔文本（保留），但 **PDF 表格/图片结构丢失**。
  3. **已有 6 个文档但只有 5 个有 embedding**（文档2 original_text 为空 → 0 chunk，embedding 失败）。旧文档在 embedding 关闭时上传。
  4. CHUNK_SIZE=500字符，300页≈15万字符 → ~300 chunks，pgvector 可承载（百万级），但大数据量需建 ivfflat/hnsw 索引优化。
- **建议**：若要支撑"300页有图有文字表格 PDF"，需：① 换 PDF 解析器（如 pdfplumber / 用 OCR 处理扫描页）；② 表格用结构化提取；③ 大向量量加 HNSW 索引。
