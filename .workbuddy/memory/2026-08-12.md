## 登录 500 "internal error" 修复 (pull 新 commit 后 DB schema 漂移)
- 现象：前端登录报 internal error。后端日志 `UndefinedColumnError: column users.phone does not exist`
  （SELECT users.phone ... WHERE username='admin'）。
- 根因：从另一台电脑 pull 的最新 commit 给 `User` 模型加了 `phone` 字段（`backend/app/models/user.py`），
  但数据库是用 `init_db()` 的 `Base.metadata.create_all` 建的（**从未跑过 alembic**，库里无 `alembic_version`
  表），新字段不会自动加进已有表 → 查询挂掉。
- **关键事实**：backend 镜像里 **没装 alembic**（requirements.txt 无 alembic；`python -m alembic` 误把项目
  `alembic/` 配置目录当包）。迁移文件 `001_init_schema.py` 已含 phone，但工具不可用、且库未迁移。
- 修复：用一段脚本 (`scripts/diff_schema.py`，async `MetaData.reflect` 比对模型 vs 库) 算出差异——只有
  `users.phone` 一列缺失，无缺表/无其它改动。直接 `ALTER TABLE users ADD COLUMN phone VARCHAR(32);` 解决。
  验证：`POST /api/v1/auth/login` 用 admin/admin123 返回 200 + JWT。
- **结论**：后端是卷挂载 `./backend:/app`，新代码已被 --reload 实时加载，**无需重建镜像**；前端是构建时
  bake 进镜像，需 `docker compose up -d --build frontend` 重建才反映新代码。
- celery-worker/beat 显示 `unhealthy` 是**假警报**：与 backend 同镜像，继承了 backend Dockerfile 的
  HEALTHCHECK(探 :8000/health)，但 celery 不提供 HTTP → 探活必失败。日志实际 `ready`、已连 redis，正常。
- 经验：pull 他人 commit 后若报 DB 列错误，先比对模型与库（diff_schema.py），别盲目重建镜像。
