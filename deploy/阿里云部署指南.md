# LG 船舶管理 ERP · 阿里云 ECS 部署指南

本指南面向**运维不熟**的同学，目标：在阿里云上从零建一台 ECS，跑一条命令，站点用公网 IP 直接访问（http）。域名备案完成后再切 HTTPS。

> 你只需要做两件事：**在控制台点几下建服务器** + **在本机粘贴一条命令**。剩下的脚本全自动。

---

## 一、在阿里云控制台创建 ECS（约 10 分钟）

1. 登录 [阿里云控制台](https://ecs.console.aliyun.com) → 进入「**云服务器 ECS**」。
2. 左侧菜单「实例与镜像 → 实例」→ 右上角「**创建实例**」。
3. **基础配置**：
   - **地域**：选离你近的，例如「华东 1（杭州）」。
   - **付费方式**：按量付费（测试）或包年包月（长期）自选。
   - **实例规格**：推荐 **4 vCPU 8 GiB**（如 `ecs.g7.large` 或共享型 `ecs.s6`）；最低 **2 vCPU 4 GiB** 也能跑（AI 服务轻量，不加载大模型时足够）。
   - **镜像**：选 **Alibaba Cloud Linux 3（64 位）** ← 推荐，默认 root 直登、运维最省心；也可选 Ubuntu 22.04（注意默认用户是 `ubuntu`，见下方说明）。
   - **存储**：系统盘选 **ESSD 云盘**，**40–100 GiB**。
4. **网络与安全组**：
   - **公网带宽**：选「按使用流量」，峰值 **5 Mbps**（省钱）；或固定带宽。
   - **公网 IP**：务必勾选「分配公网 IPv4 地址」，记下这个 **公网 IP**。
   - **安全组**：「新建安全组」，在**入方向**放行以下端口：
     | 端口 | 协议 | 用途 |
     |---|---|---|
     | 22 | TCP | SSH 登录 |
     | 80 | TCP | 网站 http（当前用） |
     | 443 | TCP | 网站 https（备案后切） |
     | 9000 | TCP | MinIO 文件下载（浏览器需公网可达） |
     出方向保持默认「全部」即可。
   - ⚠️ **安全说明**：9000 暴露会让 MinIO API 公网可达。脚本已自动生成强随机密码，对内网工具可接受；若要求更严，可后续改为 VPN / 反代，仅放行 22/80/443。
5. **密钥对**：创建**密钥对**并下载 `.pem` 私钥（用于 SSH 登录）。或设置 root 密码（不推荐明文密码）。
6. 确认下单，等待实例「运行中」。

## 二、在本机执行一条命令部署

> 前提：你的电脑装了 Git（自带 Git Bash），且能用刚才的密钥 SSH 登录 ECS。

打开终端（Windows 用 **Git Bash**），进入本项目目录，执行：

```bash
# 把 <公网IP> 换成你的 ECS 公网 IP，<私钥路径> 换成下载的 .pem
LG_SSH_KEY=~/.ssh/aliyun.pem bash deploy/deploy-to-ecs.sh <公网IP>
```

脚本会自动：打包代码 → 上传到 ECS → 在 ECS 上装 Docker → 配置国内镜像加速器 → 生成随机密钥 → 探测公网 IP → 构建并启动整套服务。

跑完最后会打印：

```
访问地址:  http://<你的公网IP>/
```

浏览器打开这个地址即可。**默认管理员账号**为 `admin / admin123`（种子数据；正式使用请尽快改密码）。

> **Ubuntu 镜像注意**：默认用户是 `ubuntu` 且无密码 sudo。请在命令里指定用户并改用交互式 ssh 首次配置：
> `ssh -i ~/.ssh/aliyun.pem ubuntu@<IP>` 登录后 `sudo visudo` 确保 NOPASSWD，或直接在 ECS 上手动跑 `sudo bash deploy/bootstrap.sh`。**推荐直接用 Alibaba Cloud Linux 3（root），最省事。**

## 三、备案后升级到 HTTPS（可选）

1. 域名做 **ICP 备案**（阿里云「备案」入口，约几个工作日）。
2. 域名 **DNS 解析**：添加 A 记录指向 ECS 公网 IP。
3. 在 ECS 上编辑项目根目录 `.env`：
   ```
   SITE_ADDRESS=yourdomain.com
   ```
4. 重新加载：
   ```bash
   docker compose -f docker-compose.prod.yml up -d caddy
   ```
   Caddy 会自动申请并续期 Let's Encrypt 证书，之后用 `https://yourdomain.com` 访问。

### ⚠️ HTTPS 下的 MinIO 混合内容问题
页面变 https 后，`http://IP:9000` 的预签名文件链接会被浏览器**拦截（mixed content）**。两种解法：
- **（推荐）让 MinIO 也走 Caddy**：在 `deploy/Caddyfile` 的 `handle` 区加一段，并把 `.env` 的 `MINIO_PUBLIC_ENDPOINT` 设为 `https://yourdomain.com/minio`：
  ```
  handle /minio/* {
      uri strip_prefix /minio
      reverse_proxy minio:9000
  }
  ```
  然后 `docker compose -f docker-compose.prod.yml up -d caddy backend`。
- **（临时）接受 http 文件链接**：文件下载仍走 `http://IP:9000`，仅文件链接不是 https。

## 四、日常运维

```bash
# 查看各服务状态
docker compose -f docker-compose.prod.yml ps

# 查看日志（如后端报错）
docker compose -f docker-compose.prod.yml logs -f backend

# 重启全部
docker compose -f docker-compose.prod.yml restart

# 更新代码：在本机改完/拉取后，重新上传并构建
LG_SSH_KEY=~/.ssh/aliyun.pem bash deploy/deploy-to-ecs.sh <公网IP>
```

**数据备份**：Postgres、MinIO 数据存在 ECS 磁盘卷里。建议定期给 ECS 打**快照**（控制台「实例 → 快照」），防止误删/磁盘损坏。

**改代码后**：任何后端/前端代码改动，都必须重新构建镜像才能生效：
```bash
docker compose -f docker-compose.prod.yml up -d --build
```

## 五、端口 / 架构速查

| 对外端口 | 服务 | 说明 |
|---|---|---|
| 80 | Caddy | 网站入口（反代 /api → backend，其余 → frontend） |
| 443 | Caddy | HTTPS（备案后） |
| 9000 | MinIO | 文件下载公网地址 |
| 22 | SSH | 登录 |

内部服务（不暴露）：Postgres(5432)、Redis(6379)、backend(8000)、ai-service(8001)、celery、MinIO 控制台(9001)。
